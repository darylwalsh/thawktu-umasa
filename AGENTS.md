# Repository Guidelines

## Purpose

A Python starter with pinned tooling, local/CI guardrails, and agent-maintained workflows.
The accepted design is in `intent/0001-python-starter-baseline/`; the initial package and mise/uv toolchain are available.

## Commands

Tasks tagged `(from NN)` remain planned until their delivery task lands; remove each marker when implemented. See the active spec's Tasks section for details.

- `mise run setup` — sync locked dependencies; install hooks (from 04).
- `mise run run` — run the demo package.
- `mise run fmt` — format Python.
- `mise run fmt:check` — check formatting.
- `mise run lint` — lint Python.
- `mise run lint:fix` — apply lint fixes.
- `mise run typecheck` — run strict pyright.
- `mise run test` — run pytest with coverage.
- `mise run lock:check` — check lockfile freshness.
- `mise run secrets` — scan history and tracked files (from 04).
- `mise run secrets:check` — validate encrypted fnox values (from 04).
- `mise run watchlist:check` — validate the watchlist (from 07).
- `mise run report:check` — validate reports against facts (from 07).
- `mise run check` — run format, lint, types, tests, then lock verification; extended in 04 and 07.
- `mise run check:aw` — compile workflows and check generated drift (from 06).
- `mise run evals` — evaluate agent configuration; requires agent credentials, separate from check (from 06).
- `mise run commit` — create a guided conventional commit (from 04).
- `mise run bump` — preview version/changelog changes with `--dry-run`; release PR flow from 05 (from 04).
- `mise run labels` — provision repository labels; maintainer authentication required (from 06).
- `mise run watch:preview` — trigger a tooling-watch run; GitHub authentication required (from 07).

## Verifying your work

Run `mise run check` before reporting a task complete and paste its output. If a test fails, fix the code rather than weakening the test.
For documentation changes, also check whitespace and links. Report unavailable checks explicitly. Agent evals arrive in task 06.

## Conventions

- Follow `.editorconfig`: UTF-8, LF, final newline; Python uses four spaces, Markdown/TOML/YAML/JSON two.
- Use `src/python_starter/`, strict typing, and annotated public functions; explain any `Any`.
- Use `# pyright: ignore[ruleName]  # reason` and `# noqa: CODE  # reason`; never bare ignores. Record per-file ignore decisions in `decisions.md`.
- Tests use `tests/test_*.py`, assert behavior, and make no network calls. Pytest disables sockets and treats unexpected warnings as errors; coverage must stay at least 95%.
- Conventional Commits: `feat fix docs style refactor perf test build ci chore revert`; scopes optional.

## Invariants

1. `mise run check` passes with no secrets and no network beyond package install.
2. Agents never push to `main`. Every change arrives as a PR.
3. Tool versions are exact pins. `pyproject.toml` and `uv.lock` change together.
4. In a bug fix, the reproducing test is committed first and its assertions are not changed by the fix.
5. Feature requests become an `intent.md` before any code.
6. Tooling-watch PRs change only `reports/tooling-watch/**`. `tooling/watchlist.toml` is changed only by humans.
7. `CLAUDE.md` stays a pointer to `AGENTS.md`.
8. Generated files (`uv.lock`, compiled `.lock.yml`, `CHANGELOG.md`, report facts files) are regenerated by their tool, never hand-edited.
9. Changes to agent configuration (`AGENTS.md`, `REVIEW.md`, `.claude/**`, agent workflow prompts) come with an eval run.

## Git conventions

- One task per short-lived branch/PR from the requested base (default `main`); make atomic commits, review staged changes, and commit only task-owned files.
- Never use `--no-verify`, force-push `main`, or disable Claude Code hooks.
- Follow `REVIEW.md`: independent agent review, then human code-owner approval; only eligible report PRs use the deterministic merge exception.
- Keep changes within the assigned task; include acceptance evidence in the PR. Regenerate tool-owned files with their tool.

## Agent code search

Use Semble `search` to locate implementations, then read the returned file and line directly. Select `content="docs"`, `"config"`, or `"all"` for non-code searches. Use grep only when every occurrence of a literal is needed.
